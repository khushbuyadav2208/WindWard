## Part 1: customer demo (0:00–3:46)

1. **Business problem:** tomorrow's wind is uncertain, yet the electricity purchase decision happens today. Introduce the national wind pilot and January historical scope.
2. **Decision-time overview:** explain the explicit configurable 10:00 London cutoff, the decision-date basis, and 1 February deliveries following a 31 January purchase.
3. **Four KPIs:** latest selected forecast, typical miss (MAE), large-error sensitivity (RMSE), directional bias. Describe why wind over-prediction can leave a buyer short.
4. **Generation chart:** compare actual and forecast, hover for the selected publication and cutoff, and explain the visibly disclosed hourly hold.
5. **Signed error:** positive errors mean less wind than expected; negative errors mean more. Historical P90 is not a future confidence interval.
6. **Filters:** demonstrate one-day range and decision settings. All relevant charts, counts, metrics and CSV share the filter contract.
7. **Accuracy:** explain MAE, RMSE, MAPE, WAPE, bias and the maximum miss. Note MAPE's sensitivity at low output.
8. **Breakdowns:** daily MAE, delivery-half-hour patterns and error distribution focus investigation on difficult periods.
9. **Traceability:** search and sort the interval table, show publication/alignment, explain full-selection CSV export.
10. **Credibility and value:** show methodology and health, distinguish wind uncertainty from a full demand/price procurement model, and close on transparent decision support.

## Part 2: technical review (3:46–8:19)

1. **Architecture:** React → FastAPI → pure analytics / repository → Elexon. Explain responsibility boundaries.
2. **Selection:** show `decision_time` and `select_forecast`; state publishTime ≤ cutoff, latest eligible vintage, no hindsight. Distinguish delivery, publication and lead time.
3. **Validation/alignment:** expected half-hours, finite generation, aware timestamps, WIND filtering, duplicate/conflict handling and explicitly held hourly values.
4. **Metrics:** matched-pair denominator, error sign, MAE/RMSE/bias, zero-actual handling, reuse of the same metric function for breakdowns.
5. **Integration:** publication-window fetching, three-day chunks, four concurrent requests, bounded retries/timeouts and boundary data.
6. **Reliability/security:** genuine snapshot and SHA manifest, source age, single-flight atomic refresh, retention of last good data, token protection and safe errors.
7. **Frontend/API:** component folders, abortable request hook, one filter contract, relative `/api` paths, OpenAPI and CSV.
8. **Tests:** business invariants, real-snapshot integration, UI components, end-to-end browser interactions, mobile and accessibility, patched dependencies.
9. **Docker/deployment:** two non-root services, Nginx proxy, health check, volume, Vercel single-origin entrypoint. State Docker and live-publication verification limits honestly.
10. **Tradeoffs:** bounded pilot, no unnecessary external datasets/infrastructure, instance-local serverless cache, no financial optimization, explicit assumptions, docs/audit handover.

## Reproduce the local video on Windows

Install and start the app first. These optional tools are not needed to run the product:

```powershell
./.venv/Scripts/python.exe -m pip install -r scripts/requirements-tools.txt
cd frontend
npx playwright install ffmpeg
cd ..
./scripts/narrate-demo.ps1
./.venv/Scripts/python.exe scripts/demo_timing.py
node scripts/record-demo.mjs
./.venv/Scripts/python.exe scripts/render_demo.py
```

By default the recording uses local Edge in hidden/headless mode at http://127.0.0.1:5173. Set `DEMO_BASE_URL` to a running production origin or `PLAYWRIGHT_CHANNEL` to another installed Playwright browser when necessary. The narration helper requires the Windows `Microsoft Zira Desktop` voice. Recording takes the actual duration of the demo; rendering takes additional time.

No credentials, personal desktop windows or unrelated documents are recorded. Generated media and screenshots stay in ignored `artifacts/`; the source includes the script and generation tools, not bulky video files.
